# Supabase setup guide

Follow these steps to let the Book Review Tracker sync its IndexedDB data with Supabase. If you are also experimenting with the new standalone Discord bot (`discord-bot/`), note that it currently manages its own configuration—the Supabase pieces below remain focused on the web app.

## 1. Create a project

1. Sign in at [supabase.com](https://supabase.com/) and create a new project (the free tier is fine).
2. Wait for Supabase to provision the Postgres instance and note the **Project URL** and **anon public key** from the Project Settings → API page. You will paste these into the frontend `.env.local` later.

## 2. Define the database schema

Open the SQL Editor inside Supabase and run the script below to create the tables the app expects. The `generated by default as identity` clause keeps Supabase free to assign keys when you insert manually, while still letting the app upsert explicit IDs that match the IndexedDB rows.

```sql
-- Books that power the main library grid
create table if not exists public.books (
  id bigint generated by default as identity primary key,
  title text,
  "titleLower" text,
  author text,
  "authorLower" text,
  status text,
  cover jsonb,
  "openLibraryUrl" text,
  "openLibraryIdentifiers" jsonb,
  availability jsonb,
  "createdAt" timestamptz,
  "updatedAt" timestamptz
);

-- Per-book review details (rating, notes, status)
create table if not exists public.reviews (
  id bigint generated by default as identity primary key,
  "bookId" bigint references public.books(id) on delete cascade,
  rating numeric,
  text text,
  status text,
  unread boolean,
  "createdAt" timestamptz,
  "updatedAt" timestamptz
);

-- Helpful index for lookups by book
create index if not exists reviews_book_id_idx on public.reviews("bookId");
```

## 3. Enable Row Level Security

```sql
alter table public.books enable row level security;
alter table public.reviews enable row level security;
```

RLS must be on for Supabase policies to work. The app currently relies on anonymous access, so we add permissive policies in the next step.

## 4. Grant anonymous CRUD access (no auth yet)

Run the following SQL to let the built-in `anon` role read and write both tables. These policies keep things open until you add authentication.

```sql
-- Books policies
create policy "books_read" on public.books
  for select
  using (true);

create policy "books_insert" on public.books
  for insert
  with check (true);

create policy "books_update" on public.books
  for update
  using (true)
  with check (true);

create policy "books_delete" on public.books
  for delete
  using (true);

-- Reviews policies
create policy "reviews_read" on public.reviews
  for select
  using (true);

create policy "reviews_insert" on public.reviews
  for insert
  with check (true);

create policy "reviews_update" on public.reviews
  for update
  using (true)
  with check (true);

create policy "reviews_delete" on public.reviews
  for delete
  using (true);
```

> **Tip:** If you later add authentication, replace the `using (true)` / `with check (true)` clauses with predicates that scope records per user.

## 5. Optional tuning

- Turn on **Database → Replication → Realtime** for the `books` and `reviews` tables if you plan to add live updates later. The current app polls only at startup, so this step is optional.
- Seed the tables with a few manual entries if you want to see remote data appear immediately on first load.

## 6. Wire the keys into the frontend

1. Copy the project URL and anon key from Project Settings → API.
2. Inside the repo, create `src/frontend/.env.local` (this file is ignored by Git) with:
   ```bash
   VITE_SUPABASE_URL="https://your-project-id.supabase.co"
   VITE_SUPABASE_ANON_KEY="your-public-anon-key"
   ```
3. Restart `npm run dev` (or `npm run build`) so Vite picks up the environment variables.

When those variables are present the app will pull the remote snapshot during bootstrap, merge it into IndexedDB, and mirror future edits back to Supabase. If the keys are missing or Supabase is unreachable, the UI automatically falls back to local-only mode.
